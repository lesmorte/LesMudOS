# Quest journal (built 26 November 2026)

Owner's request: "I'd like the mudlet plug-in enhanced to have a quests tab. Active completed and abandoned. For active it should have all conversations that involve the quest. Completed or abandoned should have a small summary." The journal lives in the game and is saved with the character; the Mudlet tab only shows what the game sends (`Char.Quests.List` and `Char.Quests.Log`, in `docs/specs/gmcp.md`). Code: `/std/questjournal` (the journal, the commands, the GMCP), `/std/npc` (where dialogue is recorded), `clients/mudlet/src/quests.lua` (the tab). Tests: `tests/quest_journal_test.py`, `tests/gmcp_test.py` (`GMCP_ONLY=quests`), `tests/sandbox_test.py`, `clients/mudlet/test/quests_test.lua`.

## Decisions for the owner
Each was built as written. Where it says "alternative" that is what was not done.
1. **The journal is a new base class between `Living` and `Adventurer`** (`/std/questjournal`), not more code inside `adventurer.cs`. The saved `quests` and `questTitles` moved there, so every existing save loads unchanged. Alternative: fields in `Adventurer`; rejected to keep the three busy files small and the journal in one place.
2. **Quest state stays three-valued for everything that already asks** (`QueryQuest` 0, 1, 2: the travel pass, the Guild reader, class and Renown gates all test `== 2`). A fourth state "abandoned" exists only in the journal, and reads as 0 through `QueryQuest`, so an abandoned quest is, to the rest of the game, a quest never taken. Alternative: a new numeric state; rejected because it would touch every gate.
3. **Each quest is defined by its giver** (`DefineQuest` in the NPC: title, area, the two authored summaries, the items to remove, the objectives, whether it can be abandoned). The journal asks the giver; nothing about a quest is stored in a central table. Alternative: a quest daemon; rejected, three quests do not need one.
4. **Dialogue is tagged at the source.** An NPC line, a chat line or a topic carries the id of the quest it belongs to (`AddChat(line, quests)`, `AddTopic(keywords, line, quests)`, `QuestSay`). The journal never reads game text. The player's own side is recorded as `ask NAME about TOPIC` and nothing else the player types.
5. **Before the quest is accepted the lines go to a hidden "offered" buffer** (6 entries, 1,500 characters). The offer and the player's question appear in the log in order the moment the quest is accepted. The buffer is never listed and never sent: nothing about an un-offered quest reaches the client, and a quest only spoken of stays invisible until accepted.
6. **Bounds, as constants in `/std/questjournal`:** an active quest keeps its newest 80 entries and 8,000 characters (an entry at most 1,200 characters); a character holds 60 quests; a summary is at most 400 characters. When the oldest entries are dropped the log begins with `(earlier conversation not kept)` (a `gap` entry with seq 0) and the client is sent the whole log again with `reset`.
7. **Objective progress is noted by polling** (about once a second while in the game) from the same facts the quest text uses (kill credit and carried items), so no quest code had to change to report progress. Each change is a `note` entry in the log. Alternative: have each quest call the journal; rejected, it would touch every quest.
8. **Dates are real timestamps shown as in-world dates** ("the 1st Day of Deepfrost, Year 1") through `/secure/chronicle`. A save from before the journal has no date for old quests, and the tab leaves the date out rather than inventing one.
9. **Summaries.** Each quest definition has two authored lines in the game's voice, one for completed and one for abandoned. A quest with none gets a plain generated line (`You completed "NAME" for GIVER.` / `You gave up "NAME", which GIVER had given you.`). Every existing quest has authored text (the list is in the final report, and in `rowan.cs` and `sister_merewyn.cs`). The texts say nothing the player was not told by that quest.
10. **Completed and abandoned quests keep the summary, the date, the giver and (completed) the reward.** The conversation is dropped at that moment and a `reset` with no entries tells the client.
11. **`abandon NAME` and `quest abandon NAME`, with a confirmation** (the game asks `(y/n)`; only `y` or `yes` proceeds, and the state and the fight check are made again at that moment). Abandoning is refused in a fight. It is allowed for any active quest unless the definition says `abandonable: no`; **no real quest is marked**, only a test fixture is. On abandon: the quest's items are removed (today only the Overseer's Orders), the quest reads as 0, the giver offers it again as to a newcomer, the log is dropped, rewards already given are kept, and Chronicle and Renown are untouched. A retaken quest starts a fresh log.
12. **Where the code made a request silly: "counters reset".** There are no per-quest counters in the game: kill credit is the character's own history (`QueryKilled`) and is not undone, so a character who retakes "Clear the Cellar" after killing the Overseer is a newcomer who has already killed it, and Rowan lets them report at once. Recommendation: leave it; the alternative is a per-quest kill ledger, which is a larger change.
13. **The travel pass and other quest gates** all test `QueryQuest == 2`. Abandoning needs an active quest, so it can never take away a completed one, and the pass is an item that is not removed. Nothing gated on quest state can be reached by abandoning.
14. **GMCP is sent from the character body**, not from `gmcp.cs`: the list at login and on any change (coalesced to one in 250 ms, like `Char.Vitals`), a log whole at login per active quest then one entry at a time with a sequence number. A client that did not announce `Char` gets nothing. The package asks for `Char 1`, which already covers `Char.Quests`; the package's request string did not change.
15. **The Mudlet tab is a docked panel on the right of the main window.** The package had no tabs, so one was made: a "Quests" header, three section tabs, a paged list, a detail area. Alternative: a Geyser tab window; rejected, the panel is simpler to get right without a Mudlet to try it in.
16. **Commands:** `quests` (as before, plus a counts line when you have any), `quests completed`, `quests abandoned`, `quest NAME`, `quests NAME`. The line "You have no quests." is unchanged.
17. **Sandbox.** A wizard's code cannot write another character's journal: `QuestHeard` and the writing form of `SetQuest` accept only trusted real callers (or a wizard in their own workshop), and only for an NPC in the same room as the player. `QueryJournal` is a read-only function for tests. Checked in `tests/sandbox_test.py`.

## What the player sees
- `quests`: the list as before, then a line `N completed, M abandoned.` with the commands that list them (only once you have any).
- `quests completed` / `quests abandoned`: name, date, giver, summary (and reward when completed).
- `quest NAME`: for an active quest the objectives and the conversation; for the others the summary.
- `abandon NAME`: `Abandon "NAME"? The conversation will be forgotten, but GIVER will offer it again. (y/n)` (with ", and what you carry for it taken back" when the quest has items).

## Recording
Recorded in `Npc.QuestSay` (an NPC speaking on a quest), `Npc.Answer` and `Npc.RecordQuest` (a topic: the question and the answer) and `Npc.Talk` (tagged chat), each calling `QuestHeard` on the player. Rowan and Sister Merewyn tag their lines through `Speak(line, quest)`.

## Limits and what is not done
- The log holds what NPCs say about the quest and what the player asks, not combat or other talk.
- Nothing is kept for a quest that was only spoken of, once the player abandons it, except a short buffer.
- The Mudlet tab has never been loaded in a real Mudlet (see `docs/MUDLET.md`).
